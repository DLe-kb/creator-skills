# 操作手册

本文件只记录已经成熟、会重复使用的操作流程。不要把所有工作方法都写进这里。

## 使用原则

- 先写项目真实流程，再考虑抽成 skill。
- 只记录以后还会照着执行的步骤。
- 涉及外部账号、权限、发布、删除、覆盖、移动、付费资源时，先做只读检查和 dry-run，并在真实写入前请求当前对话确认。
- 不记录密钥、token、cookie、App Secret 或完整凭证文件。

## 新对话启动

只恢复上下文：

```text
请从这个项目继续。先读取 AGENTS.md 和 PROJECT_STATE.md。
如果 PROJECT_STATE.md 指向当前活跃的 task-states 文件，只读取相关任务状态。
然后用 5-10 行告诉我当前目标、最近进展、下一步和需要我决策的问题。
在我确认前不要改文件。
```

直接推进：

```text
请从项目状态恢复上下文，直接推进当前下一步。
执行前先做只读检查；如果涉及删除、覆盖、移动、联网安装、外部写入、发布、权限或账号操作，先停下来说明原因并请求确认。
完成后检查是否需要更新 Harness 文件。
```

## 单轮任务检查

执行前确认：

- 目标和完成标准是否明确？
- 是否有不能动的文件、目录或外部系统？
- 是否需要先做只读检查、联网核查、dry-run 或备份？
- 是否会触发用户确认门？

完成前确认：

- 是否有验证证据？
- 是否改变了当前状态、下一步、决策、待讨论问题、资料、流程或经验？
- 是否需要更新 `PROJECT_STATE.md`、`DECISIONS.md`、`DISCUSSION_QUEUE.md`、`REFERENCES.md`、`RUNBOOK.md` 或 `LESSONS_LEARNED.md`？

## 阶段契约模板

成熟流程如果仍需要用户逐步盯梢，在这里定义阶段契约。

```text
阶段：
输入标准：
输出标准：
自检清单：
下游验收：
证据：
返工规则：
返工上限：
用户确认门：
```

执行循环：

```text
阶段执行
-> 自检
-> 记录证据
-> 下游验收
-> 合格：进入下一阶段
-> 不合格：写返工单并回到对应阶段
-> 达到返工上限：升级给用户
```

返工单格式：

```text
打回阶段：
问题类型：
证据：
返工要求：
返回阶段：
返工次数：
是否需要用户决策：
```

证据必须具体，不能只写“已检查”。例如测试输出、截图、抽样时间点、文件数量、缺失字段、渲染参数、抽帧路径或检查清单结果。

## 状态文件更新规则

- 当前目标、进度、下一步、阻塞项或活跃文件变化：更新 `PROJECT_STATE.md` 或当前 `task-states/*.md`。
- 形成后续应继续遵守的决定：更新 `DECISIONS.md`。
- 出现需要用户选择、确认或补充的信息：更新 `DISCUSSION_QUEUE.md`。
- 新增重要资料、链接、工具或外部系统说明：更新 `REFERENCES.md`。
- 沉淀出可重复执行的操作步骤或阶段契约：更新 `RUNBOOK.md`。
- 暴露协作问题、重复错误或更好的工作方式：更新 `LESSONS_LEARNED.md`。

如果对应文件尚不存在，但本轮出现触发条件，就创建该文件；否则不要为了凑齐模板而创建空文件。
