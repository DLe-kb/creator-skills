# HTML 审计报告视觉系统

## 适用范围

本规范约束 `analysis-report.html` 的稳定板式。它服务于企业人工审阅和证据回溯，不是营销落地页，也不是展示型数据大屏。

除非用户明确要求重新设计，所有报告必须继承本视觉系统。样本数量、内容路线和证据规模可以变化，但页面骨架、信息层级和视觉语言不得随意更换。

## 稳定页面骨架

图文根节点使用：

```html
<body data-report-template="xhs-image-post-audit">
```

视频根节点使用 `<body data-report-template="xhs-video-post-audit">`。除模板标记和媒体专属内容组件外，两者使用完全相同的页面骨架、变量、组件和响应式规则。

页面至少包含以下可校验节点：

- `data-report-part="navigation"`：顶部固定或吸顶导航，提供主要章节锚点。
- `data-report-part="audit-hero"`：浅色审计式首屏，直接呈现分析对象和报告用途。
- `data-report-part="audit-meta"`：报告编号、样本范围、证据资产、数据时点或缺失范围等审计元信息。
- `data-report-part="executive-summary"`：首屏深色核心结论，列出 3 至 5 条最重要发现及其证据等级。可见标题只能使用“核心结论”。
- `data-report-part="evidence-gallery"`：逐篇完整页面证据和配图序列所在区域。
- `data-report-part="lightbox"`：证据图片点击放大容器。

首屏顺序为“分析对象与用途 → 审计元信息 → 核心结论摘要”。不要先展示大面积装饰图、品牌口号或统计数字墙。

## 视觉语言

- 页面背景使用浅灰纸张感，主要内容面使用白色或近白色。
- 正文使用深墨色；主强调色使用克制的砖红色；风险可沿用红色，辅助信息可用中性灰或低饱和色。
- 深色块只用于首屏结论摘要或少量关键结论，不把整页做成深色主题。
- 圆角控制在 `0-6px`，避免大圆角、胶囊标签和漂浮式卡片堆叠。
- 标题字号与报告层级匹配。首屏标题清楚但不过度营销；章节标题适合长篇审阅。
- 字距保持 `0`，不使用外部字体、渐变、光斑、装饰性 SVG 或纯装饰图片。
- 章节用语采用“样本范围、核心发现、组成要素、主要载体、内容路线、说服结构、逐篇证据、证据边界”等语义标题，不显示 `01 · 范围` 一类章节编号眉题。

## 信息组件

- 元信息使用定义列表、表格或稳定网格，不使用统计卡片墙代替审计范围。
- 证据等级至少区分：样本事实、跨样本观察、分析推断和高风险主张。
- 路线、变量和证据字段优先使用表格、分栏或横向可滚动结构；卡片只用于单条路线、单篇样本或确实需要边框的独立对象。
- 逐篇证据使用模板 3 的固定卡片：顶部为原帖大标题、作者/内容类型/路线副标题和分项互动指标；主体左侧展示完整页面，右侧使用“标题、正文、图片、风险”四项分析；原始配图序列置于底部折叠区，并保留顺序和图注。
- 所有可查看证据图添加 `data-zoom`，并可通过 `data-report-part="lightbox"` 的容器放大。

## 结论与原帖证据配对

- 报告采用“结论旁核验”的证据组织，不采用“前面连续文字、末尾统一看图”的组织。
- 核心发现、组成要素、主要载体、内容路线和说服结构中的主要结论，应在同一分析块内配套原帖图片证据。
- 每个结论证据组使用 `data-evidence-group="..."`；组内每张图或图片复用槽使用非空的 `data-evidence-source="..."`，明确它来自哪条样本及哪张页面或配图。
- 标题与正文分析优先使用完整页面截图，让标题、正文和上下文同时可见；封面分析优先使用首图；图片信息卡、质地、泡沫、场景和收口分析使用对应原始配图。
- 图片下方必须说明“这张图支持什么判断”，不能只写“样本截图”或重复文件名。
- 同一原帖图片可以在多个分析位置复用，但正式 HTML 中应避免重复写入大段 Base64；可从逐篇证据区的已内嵌图片克隆到就地证据槽。
- 末尾逐篇证据区承担完整回溯与图片顺序核验，不能作为前面分析章节缺少图片的理由。

## 固定结论证据组件

模板3的结论证据组件是统一板式的标准实现，不得仅复刻配色后重新设计结构。每个主要结论使用以下顺序：

```html
<article class="finding-grid" data-evidence-group="..."><!-- article 或 div 均可 -->
  <div class="finding-copy">
    <h3>结论标题</h3>
    <p>结论说明与适用范围</p>
    <div class="finding-points">
      <div class="finding-point"><strong>分析维度</strong><span>具体判断</span></div>
    </div>
  </div>
  <div class="evidence-stack">
    <figure class="evidence" data-evidence-source="样本ID与图片ID">
      <img data-zoom src="data:image/..." alt="可核验描述">
      <figcaption>这张原帖图片支持什么判断，以及不能支持什么。</figcaption>
    </figure>
  </div>
</article>
```

- `.finding-copy h3` 统一显示 `P1` 审计优先级，不为不同报告另造眉题体系。
- `.finding-points` 桌面端为两列、手机端为一列；每组保留 2 至 4 个有效分析点。
- `.evidence-stack` 使用横向证据带，`figure.evidence` 图片视窗固定为约 `340px` 高并保持 `object-fit: contain`。
- 路线证据也使用同一组件。路线字段可以先放在 `.route` 中，但原帖图片仍通过标准结论证据组就地出现。
- 不允许用左右编辑栏标题、瀑布式图片卡、独立统计卡或新的证据卡命名替代该组件。

## 响应式与打印

- 桌面端建议内容宽度为 `1180-1440px`，长表格和图片序列在自身容器内横向滚动。
- 手机端首屏、元信息、路线和逐篇证据改为单列；任何长词、样本 ID 和标题都必须换行，不得撑破容器。
- 顶部导航可以横向滚动，但正文页面不得出现整体横向滚动。
- 提供打印样式，打印时隐藏吸顶导航和图片放大层，并保证正文为白底可读。

## 允许变化

- 可根据内容选择表格、路线列表、变量矩阵或证据带的具体组合。
- 可以在保持浅色纸张、深墨正文、砖红强调和审计骨架的前提下调整密度。
- 可以新增附录、指标快照或方法说明，但不得替代必需章节和首屏结论摘要。

## 禁止变化

- 不得把审计报告改成深色品牌 Hero、营销落地页、仪表盘首页或独立的新主题。
- 不得只靠颜色和大数字表达结论，或把证据与结论拆成无法回溯的视觉卡片。
- 不得为了“更好看”删除审计元信息、证据等级、完整页面截图、图片顺序、风险边界或放大交互。
- 不得让核心发现、组成要素、路线和说服结构成为大段无图文字；也不得使用与结论无关的产品图作为装饰。
