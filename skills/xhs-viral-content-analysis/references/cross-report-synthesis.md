# 跨报告综合方法

## 目的

从多份已经完成的内容分析报告中，提炼能够跨报告回溯的共性机制、开放内容路线、媒体差异、研究对象差异和适用边界。综合分析是对既有分析结果的二次研究，不重新替代单篇内容核读，也不把正样本共性升级为爆款或转化因果。

## 触发条件

跨报告综合由用户任务意图触发，不由文件数量自动触发。

- “总结这些报告的共性”“比较几份分析的差异”“提炼内容路线”“生成综合报告”等表达，均属于明确触发。
- 用户仅上传或列出多份报告，但没有提出综合目标时，不自行扩大任务。可以提示能够进行跨报告综合，但不得直接生成综合结论。
- 输入只有一份报告时继续使用单批内容解析或报告审阅，不包装成跨报告综合。

## 最小输入

至少 2 份能够识别以下信息的分析报告或结果包：

- 稳定报告 ID、研究对象、媒体类型和分析状态。
- 纳入样本数量、样本来源和主要限制。
- 跨样本结论、内容路线、证据引用和主张边界。
- 可回溯的代表页面、配图或视频关键帧。

优先读取结构化 JSON，再读取 HTML 核对可见结论与代表证据。只有 HTML 时允许输出 `partial`，并明确缺少哪些稳定字段。报告数量不是可比性的替代条件。

## 可比性检查

综合前先建立报告台账，逐份记录：

- 平台、研究问题、产品或研究对象。
- 图文或视频媒体类型。
- 企业样本、外部公开候选或混合来源。
- `complete`、`partial` 或 `blocked` 状态。
- 正样本、负样本、普通样本和结果数据是否存在。
- 样本及证据是否可能在多份报告中重复。

`blocked` 报告不进入共性计数。`partial` 报告可以进入，但其支持的结论不得获得高于原报告的证据等级。相同样本被多份报告重复分析时只计算一次独立样本支持。

## 综合顺序

1. **标准化报告字段**：统一报告、样本、路线、证据和来源 ID。
2. **保留可比批次**：先在相同或相近研究问题内比较，不混算图文图片序列与视频时间轴。
3. **建立共性矩阵**：使用“机制 × 报告 × 样本 × 证据”记录支持、反例、缺失和冲突。
4. **提炼共性机制**：只有至少 2 份独立报告支持时，才写为跨报告重复观察。单份报告中的多样本重复仍只属于报告内共性。
5. **开放聚类路线**：按用户任务、核心张力、主要载体、产品角色和选择出口合并相近路线，不强迫全部路线进入预设分类。
6. **分析媒体差异**：图文与视频先分别归纳，再比较谁承担主要论证、如何建立理解和信任。
7. **分析研究对象差异**：描述本批内容中各对象较突出的内容位置，不写成固定产品定位或永久创作规则。
8. **划分适用层级**：至少区分本批直接支持、跨场景迁移候选、平台假设和效果因果未验证。
9. **形成内容诊断**：将共性机制压缩为面向策划与评审的问题，不新增没有证据来源的理想模型。
10. **执行矛盾检查**：检查标题、公式、结论和边界是否使用了同一证据强度。

## 共性与证据

每条核心机制必须同时保存：

- 支持报告 ID 和支持样本 ID。
- 跨报告支持证据 ID。
- 反例、冲突或缺失信息。
- 适用范围、结论类型和置信程度。
- 1 至 3 个帮助理解的代表截图或关键帧。

跨报告来源映射证明“这项机制反复出现”；代表截图证明“某个案例如何体现这项机制”。单张截图不能独立证明多报告共性。

## 路线综合

路线族使用中性、面向用户任务的名称。每条至少包含：

- 用户任务和核心张力。
- 主要信息载体。
- 适合场景和不适用条件。
- 来源路线与支持报告。
- 代表证据、反例、限制和置信程度。

多份报告支持时标记为 `cross_report_observed`；只有一份报告支持时标记为 `single_report`；主要依赖解释性聚类时标记为 `hypothesis`。低支持路线可以保留，但必须在视觉和文案上与多报告共性区分。

## 可以呈现

- 可回溯的样本与报告范围。
- 多份报告重复出现的内容机制。
- 开放内容路线及其支持来源。
- 图文、视频和不同研究对象的本批差异。
- 代表证据、适用条件、反例与证据上限。
- 从上述机制压缩得到的内容诊断问题。

## 不能呈现

- 未经数据验证的爆款公式、高转化公式或效果保证。
- 把正样本共性写成成功原因、平台算法规则或销售因果。
- 把外部公开候选写成企业确认样本。
- 把单一产品在本批内容中的突出角色写成固定产品定位。
- 内部沟通、制作说明、修改过程、版本、Gate、Skill、脚本、校验器或文件路径。
- 为填满版式而硬凑机制、路线、证据截图或产品差异。

## 输出

- `synthesis-report.html`：面向人工阅读的正式综合报告。
- `synthesis-result.json`：保存报告、样本、证据、机制、路线和适用层级的机器结果。

HTML 与 JSON 必须表达同一组结论。HTML 负责快速理解与证据核验，JSON 负责稳定引用和后续比较。
