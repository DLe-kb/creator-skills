# 共用解析核心

## 目的

从一批完整内容成品中形成可追溯的结构化结论。解析对象是完整笔记及其模块关系，不是孤立标题、单张图片或脱离上下文的互动数字。

## 最小分析单元

使用以下组合定义一个可比较批次：

> 研究对象或产品 × 平台 × 媒体形式

同一批次可以包含不同作者、账号或内容路线，但必须说明样本为何具有比较价值。图文与视频不得混入同一媒体结构统计。

如果同一输入同时包含图文和视频，先拆分媒体批次。可以说明两批内容围绕同一研究对象，但不得把图片序列与视频时间轴放进同一套频次、节奏或载体结论。

## 证据层级

对每项结论标记一种类型：

- `source_fact`：原始页面、正文、图片、评论、元数据或数据字段中可直接核对的事实。
- `observed_pattern`：多个样本中重复出现的组成或关系，不包含因果解释。
- `analysis_inference`：基于证据作出的解释，必须给出推理范围和替代解释。
- `hypothesis`：等待新样本、对照样本或真实测试验证的假设。
- `human_confirmed`：用户或授权人员明确确认的企业事实或业务结论；没有确认记录时不得使用。

对跨样本结论使用 `high`、`medium` 或 `low` 置信程度。置信程度只表示当前证据对该描述的支持程度，不表示业务效果概率。

## 样本范围

1. 为每条输入分配稳定样本 ID。
2. 记录媒体形式、可用模块、来源和数据采集时间。
3. 明确纳入、排除和排除原因。
4. 不因标题相似、产品相同或指标较高自动认定样本可比。
5. 指标只作为采集时点事实。缺少统一流量来源、投放条件、时间窗口和对照时，不作因果比较。

## 单篇拆解

先逐篇完成，再做横向总结。每篇至少回答：

- 用户被邀请完成什么阅读任务或判断。
- 面向什么问题、处境、场景或身份愿望。
- 产品或研究对象在内容中承担什么角色。
- 主要信息载体是什么。
- 各模块分别承担什么信息任务，如何前后承接。
- 使用了哪些说服节点、信任表达和决策收口。
- 哪些画面或文字支持哪些观察，哪些主张超出证据。
- 观众在关键节点前后知道了什么、相信了什么、仍犹豫什么。

不要为了形成整齐框架而补齐样本中没有的模块。

## 路线识别

内容路线必须从样本差异中产生，不使用预设分类表强行归类。

每条路线至少包含：

- 稳定路线 ID 和中性名称。
- 支持该路线的样本 ID。
- 用户任务和核心张力。
- 主要信息载体。
- 产品或对象角色。
- 模块分工与说服节点。
- 使用条件和不适用条件。
- 证据 ID、反例、限制和置信程度。

只有一个支持样本时可以保留路线，但必须标记为单样本路线，不升级为稳定规律。

## 价值转译

分析内容如何把特征写成用户价值时，使用以下关系：

> 用户阻力或任务 → 产品特征与内容细节 → 用户价值 → 产品角色与证据

区分“样本作者这样表达”和“产品事实确实如此”。个人体验、产品事实、健康效果、成分机理和竞品比较使用不同证据门槛。

## 风险与边界

至少识别：

- 可观察的包装、形态、动作、场景和页面内容。
- 需要条件化表达的个人体验。
- 需要企业资料支持的产品事实和使用方法。
- 需要更高等级证据的健康、功效、机理和结果主张。
- 需要统一条件与来源的竞品或方案比较。
- 无法确认的商业关系、素材权利和作者身份。

风险识别的结果是限制结论和暴露缺口，不是替代法律、医学或企业合规审查。

## 下游边界

解析结果可以支持下游选择内容路线、理解模块关系和识别不可越界范围，但不直接提供发布承诺。下游不得把 `observed_pattern`、`analysis_inference` 或 `hypothesis` 自动改写成企业事实。

可复刻结论只提炼功能结构、信息字段、镜头职责、成立条件和失效条件。不得复制原作者标题、口播、比喻、独特故事、连续镜头组合或其他具有表达独创性的内容。
