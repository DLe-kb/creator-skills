Project Harness
单项目脚手架 / 约束系统
总览 文件职责 按需升档 确认门 怎么用

让 Agent 在新对话里快速知道：项目是什么、做到哪、哪些不能动、下一步怎么走。

Project Harness（项目脚手架 / 约束系统）不是一堆文档模板，而是一个轻量运行机制： 用少量稳定文件保存项目事实、当前状态、可重复流程和确认边界，让 Codex / Agent 不靠聊天记忆推进项目。

2 个 默认核心文件：AGENTS.md + PROJECT_STATE.md。
按需 只有出现真实需求，才增加 RUNBOOK、DECISIONS 等文件。
门控 删除、发布、付费、权限、方向改变必须找用户确认。
证据 完成不是口头声明，要有测试、截图、抽样或文件证据。

四层关系

Hermes
多项目协调层

未来负责跨项目调度、监督、验收和汇报，不混入单项目模板。

Harness
单项目脚手架

保存项目规则、当前状态、决策、流程、资料和经验。

Runbook
成熟流程层

阶段契约、自检、下游验收、返工闭环先写进 RUNBOOK。

Skills
工具化能力层

真实跑过 2-3 次且边界稳定后，再考虑 skill、脚本或 automation。

它如何工作

每次新对话或新任务，Agent 都按“读真相源 -> 判断风险 -> 小步执行 -> 验证证据 -> 必要时落盘”的顺序推进。

01

读取入口

先读 AGENTS.md 和 PROJECT_STATE.md，确认项目规则和当前状态。

02

判断任务

明确目标、完成标准、相关文件、风险和是否需要用户确认。

03

执行最小步

只做当前目标需要的改动，不扩大范围，不顺手重构。

04

验证证据

用测试、截图、抽样、文件清单或 dry-run 证明结果。

05

更新 Harness

只有状态、决策、流程、资料或经验变化时才更新文件。

06

交付说明

说明改了什么、验证了什么、未验证什么、下一步是什么。

文件职责

每个文件只管一种真相，避免一个状态文件变成历史流水账。

AGENTS.md

项目规则入口

项目用途、语言偏好、边界、权限规则、继续项目时先读哪些文件。

PROJECT_STATE.md

当前真相

DISCUSSION_QUEUE.md

LESSONS_LEARNED.md

经验沉淀

按需升档

Project Harness 的核心不是文件越多越好，而是从轻量开始，按真实复杂度自然增加。

轻量项目

短期任务、小工具、一次性分析，或还不确定是否长期维护。默认只创建最小可用 Harness。

  • 只保留项目规则和当前状态。
  • 不预建决策、资料、经验文件。
  • 任务结束时只在状态变化时更新。

门控和返工

成熟流程不靠用户逐步盯梢，而靠阶段契约、自检证据、下游验收和返工上限。

阶段契约

每个阶段写清输入、输出、自检、下游验收、证据、返工规则和用户确认门。

下游验收

下一阶段判断上一阶段产物能否直接使用，不合格就结构化打回。

证据要求

测试输出、截图、抽样、数量、时间点、文件路径，比“已检查”更可靠。

用户确认门

删除、覆盖、发布、付费、权限、方向改变、返工上限，必须升级给用户。

谁负责什么

这张表能防止把 Hermes、Project Harness、RUNBOOK、知识库和 skill 混在一起。

层 负责 不负责 典型位置
Hermes 跨项目调度、监督、验收、汇报。 不直接替代具体项目执行。 未来 Portfolio Harness
Project Harness 单项目规则、状态、决策、流程、资料和经验。 不做跨项目总控，不追求一开始文件齐全。 00_project-harness-项目协作/
RUNBOOK 成熟可重复流程、阶段契约、检查和返工闭环。 不放一次性想法和长历史。 RUNBOOK.md
知识库 从真实项目、复盘和旧 skill 中抽离的方法论。 不自动触发，不替代项目状态。 03_knowledge-base-知识库/

做与不做

Harness 的成功标准是降低后续成本，不是制造文档工作。

应该做

  • 新项目默认轻量，只创建真正需要的文件。
  • 把当前真相写进 PROJECT_STATE.md。
  • 把成熟重复流程写进 RUNBOOK.md。
  • 把稳定判断写进 DECISIONS.md。
  • 长对话或上下文压缩前先落盘。
  • 高风险动作前停下来问用户。

不要做

  • 为了完整性复制所有模板。
  • 把 PROJECT_STATE.md 写成任务流水账。
  • 把聊天记忆当最终真相源。
  • 把一次性流程过早做成 skill。
  • 在 Harness 文档里记录密钥、token 或 cookie。
  • 未经确认删除、覆盖、发布或修改权限。
